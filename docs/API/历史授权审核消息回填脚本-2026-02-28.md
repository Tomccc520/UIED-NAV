# 历史授权审核消息回填脚本（2026-02-28）

## 目标

补齐历史 `la_user_message` 中授权审核类消息的 `extra.licenseId`，让个人中心的：

- 我的消息 -> 查看授权
- 我的授权 -> 自动定位高亮

对旧消息也能生效。

## 适用消息类型

- `license_domain_audit`
- `license_audit`

## 脚本位置

`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/scripts/backfill-license-message-extra.js`

## 默认行为

- 默认是**预演模式**，只扫描并输出报告，不写数据库
- 只有显式加 `--write` 才会真正更新 `extra`

## 使用方式

### 1. 先预演（推荐）

```bash
cd "/Users/tangxiaoda/Desktop/网站备份/HAO UIED"
node scripts/backfill-license-message-extra.js
```

### 2. 确认后写库

```bash
cd "/Users/tangxiaoda/Desktop/网站备份/HAO UIED"
node scripts/backfill-license-message-extra.js --write
```

### 3. 指定数据库连接（如本地配置不同）

```bash
cd "/Users/tangxiaoda/Desktop/网站备份/HAO UIED"
node scripts/backfill-license-message-extra.js \
  --host 127.0.0.1 \
  --port 3308 \
  --user uied \
  --password uied123456 \
  --database uied_nav \
  --write
```

## 可选参数

- `--host`：数据库地址
- `--port`：数据库端口
- `--user`：数据库用户名
- `--password`：数据库密码
- `--database`：数据库名
- `--table-prefix`：表前缀，默认读取 `la_`
- `--message-table`：自定义消息表名
- `--license-table`：自定义授权表名
- `--limit`：本次最多扫描多少条消息，默认 `0`（全量）
- `--since-id`：仅处理大于该 ID 的消息
- `--report-file`：自定义报告路径
- `--write`：开启写入模式

## 回填规则

脚本会按下面顺序补齐 `extra.licenseId`：

1. 从已有扩展字段直接归一化：
   - `extra.licenseId`
   - `extra.license_id`
   - `extra.license.id`
   - `extra.license.licenseId`
   - `extra.payload.licenseId`

2. 如果没有授权 ID，但有 `orderId / order_id`
   - 按 `user_id + order_id` 到授权表反查授权记录
   - 查到后写入标准字段 `extra.licenseId`

## 报告输出

默认输出到：

`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/docs/API/reports/license_message_backfill_latest.json`

报告会包含：

- 扫描总数
- 更新数量
- 原本已标准化数量
- 从嵌套字段补齐数量
- 从订单ID反查补齐数量
- 无法回填数量
- 非法 JSON 数量

## 发布前建议流程

1. 先执行预演模式，确认 `updated > 0` 且无明显异常
2. 再执行 `--write`
3. 登录前端个人中心，验证：
   - 我的消息里授权审核消息能点“查看授权”
   - 跳到“我的授权”后能定位到对应卡片
4. 再执行用户中心回归脚本：
   - `scripts/user-center-regression-check.js`

## 注意事项

1. 脚本只会处理授权审核类消息，不会改其他消息类型
2. 若某条历史消息既没有授权 ID，也没有订单 ID，则无法自动回填
3. 若 `extra` 不是合法 JSON，会跳过并在报告中计数
4. 建议在发布前执行一次数据库备份
