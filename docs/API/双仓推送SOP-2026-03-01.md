# 双仓推送 SOP（2026-03-01）

## 1. 适用范围

当前项目采用“双仓结构”：

- 根仓：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED`
- 前端子仓：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/frontend`

其中：

- 根仓负责后端、管理后台、脚本、文档
- `frontend/` 是独立 Git 子模块，必须单独提交、单独推送

## 2. 当前远程约定

### 根仓

- GitHub：`github_haouied`
- Gitee：`gitee_haouied`

### 前端子仓

- GitHub：`origin`（`uied-nav-frontend`）
- Gitee：`gitee`（`uied-nav-frontend`）

## 3. 固定推送顺序（必须遵守）

### 第一步：先推前端子仓

```bash
cd "/Users/tangxiaoda/Desktop/网站备份/HAO UIED/frontend"
git status -sb
git add .
git commit -m "feat: 前端功能更新"
git push origin master
git push gitee master
```

说明：

- 这一步会把真实前端代码推到 `uied-nav-frontend`
- 如果这一步没做，根仓里的子模块指针可能会变成“悬空提交”

### 第二步：再推根仓

```bash
cd "/Users/tangxiaoda/Desktop/网站备份/HAO UIED"
git status -sb
git add .
git commit -m "feat: 后端与文档更新"
git push github_haouied main
git push gitee_haouied main
```

说明：

- 根仓会记录：
  - 后端改动
  - 文档改动
  - `frontend` 子模块指针更新

## 4. 为什么必须先推前端

根仓里的 `frontend` 不是普通目录，而是一个 **gitlink**。

也就是说，根仓只记录：

- `frontend` 当前对应的是哪个前端提交

它不直接存储前端文件内容。

因此：

1. 必须先把前端提交推到前端远程
2. 然后根仓再记录这个新指针并推送

否则别人拉根仓后执行：

```bash
git submodule update --init --recursive
```

会因为找不到前端对应提交而失败。

## 6. 客户或协作者拉取代码方式

首次拉取根仓后，必须执行：

```bash
git submodule update --init --recursive
```

如果前端子模块切换到新提交后未同步拉取，可以执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

## 7. 常见错误

### 错误 1：只推了根仓，没推前端

现象：

- 其他人拉根仓后，子模块更新失败

原因：

- 根仓记录了一个前端新提交
- 但前端远程还没有这个提交

### 错误 2：在根仓里想直接提交前端文件

现象：

- 根仓里只显示 `m frontend`
- 看不到具体前端文件

原因：

- `frontend/` 是子模块
- 具体前端文件必须在 `frontend/` 仓库中提交

### 错误 3：工作区很脏，感觉“提交不了”

现象：

- 提交面板里出现大量运行时文件

处理原则：

- 不提交运行时文件
- 已经通过 `.gitignore` 和索引清理把以下目录排除：
  - `server/server/run/`
  - `server/server/typings/`
  - `docs/API/reports/*.json`

## 8. 本项目建议的日常习惯

1. 每次开发前先看两个状态：

```bash
git -C "/Users/tangxiaoda/Desktop/网站备份/HAO UIED" status -sb
git -C "/Users/tangxiaoda/Desktop/网站备份/HAO UIED/frontend" status -sb
```

2. 有前端改动时，永远先处理 `frontend/`

3. 根仓提交前，确认不要把运行时文件带进去

4. 推送顺序固定：
   - 前端子仓
   - 根仓

## 9. 一句话版本

先推 `frontend`，再推根仓。  
根仓只记录前端指针，不直接存前端文件。
