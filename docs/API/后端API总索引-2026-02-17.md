## 2. 返回结构基线

### 2.1 前台公开接口（frontend 路由）

- 成功：`{ code: 0, data: any, message: "success" }`
- 失败：`{ code: httpStatus, data: "", message: "错误信息" }`
- 归一化位置：`server/server/app/middleware/frontend_response_normalizer.js`

### 2.2 系统路由前台投稿/互动接口（system 路由）

- 成功：`{ code: 0, data: any, message: "success" }`
- 失败：`{ code: 非0, data: any, message: "错误信息" }`
- 归一化位置：`server/server/app/middleware/system_response_normalizer.js`

### 2.3 后台管理接口（system/uied 其余）

- 兼容旧基线：`{ code: 200, data: any, message: "请求成功" }`
- 业务失败：`{ code: 300/500/..., data: "", message: "错误信息" }`
- 返回位置：`server/server/app/controller/baseController.js`

## 3. 路由文件分层

- 前台公开接口：`server/server/app/router/frontend.js`
- 后台系统与部分前台兼容接口：`server/server/app/router/system.js`
- UIED 业务后台接口：`server/server/app/router/uied.js`
- 站点设置/其它模块（若存在）：`server/server/app/router/*.js`

## 4. 对接建议

- 前端官网优先使用 `frontend.js` 下接口（`/api/articles*`、`/api/pages*`、`/api/websites*`）。
- 投稿与互动可使用 `system.js` 下 `/api/article/front/*` 与 `/api/article/*` 指定公开接口。
- 管理后台继续沿用 `code=200` 语义，不建议直接按 `code=0` 改造旧页面。
- 文章管理（UIED）建议优先使用主端口：`/api/uied/articleCategory/*`、`/api/uied/articleTag/*`。
- 若历史页面仍使用旧命名，可临时走兼容端口：`/api/uied/article/cate/*`、`/api/uied/article/tag/*`。
