# 可售卖版发布清单与授权 SOP（2026-02-20）

## 1. 主干策略（你现在的方向是对的）

- 主干只维护一套“商业版完整代码”。
- Free/Pro/Enterprise 不分支，不删代码，统一通过许可证 + 功能开关控制能力暴露。
- 交付给客户时，只发放不同许可证与初始化包，不做代码分叉。

## 2. 交付包目录（建议标准）

```text
delivery/
  README-交付说明.md
  CHANGELOG-版本变更.md
  sql/
    init_schema.sql
    init_seed_basic.sql
    init_seed_demo.sql
    patch_*.sql
  config/
    app.env.example
    nginx.example.conf
  license/

    domain-whitelist.txt
  feature/
    feature-overrides.json
  docs/
    API/
    运维手册.md
    常见问题FAQ.md
```

## 3. 授权发放 SOP（标准流程）

1. 发布前健康检查（强制）：
   - `cd server/server && npm run preflight:commercial`
   - 或：`./scripts/commercial-release-check.sh`
   - 通过标准：`FAIL=0`，建议 `WARN=0`
2. 销售确认订单：客户版本（Free/Pro/Enterprise）、授权域名数、有效期。
3. 在后台许可证中心生成或录入授权：
   - `edition`：`free/pro/enterprise`
   - `status`：`active`
   - `domainLimit`：按订单写入
   - `expiresAt`：可选（0 表示长期）
4. 生成客户交付文件：
   - `license/customer-license.json`
   - `feature/feature-overrides.json`
5. 初始化客户环境：
   - 导入基础 SQL
   - 导入站点配置/分类/标签/示例数据
   - 导入 license 与 feature 覆盖
6. 验收联调：
   - `/api/uied/license/info`
   - `/api/uied/feature/list`
   - 前端 `hasFeature(key)` 与后台版本一致
7. 交付后运维：
   - 到期前 15/7/3 天提醒续费
   - 升级后只更新 license 或 feature override，不改业务代码

## 4. Free / Pro / Enterprise 对照表（首版）

| 模块 | Free | Pro | Enterprise |
|---|---|---|---|
| 站点基础配置 | ✓ | ✓ | ✓ |
| 导航分类/标签/站点管理 | ✓ | ✓ | ✓ |
| 文章管理（基础） | ✓ | ✓ | ✓ |
| 文章专题高级视觉配置 | - | ✓ | ✓ |
| 高级运营位（Banner/推荐位策略） | - | ✓ | ✓ |
| AI 批量能力 | - | ✓ | ✓ |
| 多站点/多频道高级接入 | - | - | ✓ |
| 企业级授权策略（更高域名数/白名单） | - | - | ✓ |
| 专属技术支持 SLA | - | - | ✓ |

> 说明：矩阵可继续细化到具体 feature key；发布时以许可证中心返回的 feature 列表为准。

## 5. 商业版流程（给你的一句话版）

1. 先在主干把能力都开发好。  
2. 再用 license + feature 把功能“按版本开/关”。  
3. 最后交付时只发不同授权和初始化数据，不再维护多套代码。  

## 6. 当前网址导航系统建议继续补强

- 完成“交付初始化向导”：一键导入站点设置、分类、标签、示例内容。
- 完成“客户包导出”：导出当前站点配置 + feature 覆盖 + SQL 增量。
- 完成“授权到期预警”：后台可视化提醒 + 邮件通知模板。
- 完成“运营位模板库”：内置多套首页模板（Free 精简版、Pro 增强版、Enterprise 全量版）。
