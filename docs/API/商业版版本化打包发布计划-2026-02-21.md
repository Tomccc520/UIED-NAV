# 商业版版本化打包发布计划（2026-02-21）

## 1. 目标

- 主干只维护一套商业版代码。
- 通过 `Free/Pro/Enterprise` 许可证与功能开关控制交付能力。
- 发布动作脚本化，降低人工漏项与交付不一致风险。

## 2. 本次新增流程

- 新增脚本：`scripts/release-edition-package.sh`
- 脚本能力：
  - 发布前执行健康检查（可选跳过）
  - 生成版本目录（`free/pro/enterprise`）
  - 自动生成交付模板文件：
    - `license/customer-license.json`
    - `feature/feature-overrides.json`
    - `config/app.env.example`
    - `meta/release-manifest.json`
    - `docs/API` 商业版关键文档

## 3. 标准执行命令

```bash
./scripts/release-edition-package.sh
```

自定义输出目录与版本：

```bash
./scripts/release-edition-package.sh \
  --editions free,pro,enterprise \
  --output /tmp/uied_release \
  --base-url http://127.0.0.1:8002
```

## 4. 发布目录结构（目标）

```text
release/20260221_xxxxxx/
  free/
    README-交付说明.md
    license/customer-license.json
    feature/feature-overrides.json
    config/app.env.example
    sql/README.md
    meta/release-manifest.json
    docs/API/...
  pro/
  enterprise/
```

## 5. 版本发包策略

- `Free`：基础能力，默认关闭 Pro/Enterprise 高级特性。
- `Pro`：开放 Pro，默认关闭 Enterprise 高级特性。
- `Enterprise`：完整能力，由许可证 + feature 覆盖最终控制。

说明：代码不做分叉，所有差异来自 `license + feature-overrides`。

## 6. 发布门禁（必须）

1. 健康检查：`scripts/commercial-preflight-check.js`，要求 `FAIL=0`。  
2. 许可证校验：
   - `/api/uied/license/sign`
   - `/api/uied/license/verify`
3. 能力一致性确认：
   - `/api/uied/feature/list`
   - `/api/uied/commercial/overview`
4. 交付初始化回归：
   - `/api/uied/delivery/init/preview`
   - `/api/uied/delivery/init/execute`
   - `/api/uied/delivery/package/export`

## 7. 发布 SOP（简版）

1. 冻结版本（Tag/变更说明）。
2. 执行 `release-edition-package.sh` 生成版本包。
3. 填充客户 `license/customer-license.json` 并签名。
4. 导入客户环境初始化数据与 feature 覆盖。
5. 回归关键接口与前端首页、文章页、用户中心。
6. 交付发包（源码 + 版本目录 + 授权文件 + 运维说明）。

## 8. 后续增强建议

- 增加 `--customer` 参数，自动生成客户目录与授权元数据。
- 对接 Gitee/GitHub Release 自动上传版本包。
- 增加打包结果摘要（Markdown 报告 + JSON 清单）。
